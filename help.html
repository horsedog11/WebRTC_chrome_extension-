WebRTC setup and troubleshooting

Use the working 209 extension as a comparison. Your PBX may use a different host, extension, certificate, or codec list.

Register the phone

In Settings, enter the PBX hostname, extension number, display name, and that extension’s SIP password. Set the password in the FreePBX web portal first; enter the same password in the phone when registering. The phone does not save it.

Our working example uses host phone.tonywalker.ca, extension 209, WebSocket wss://phone.tonywalker.ca:8089/ws, and SIP identity sip:209@phone.tonywalker.ca.

Our endpoint also displayed webrtc: no and media_use_received_transport: false while calls and two-way audio worked. These are observations, not values to force on another PBX. Compare the full media settings and test a call. Use FreePBX’s settings and Apply Config so its generated configuration remains consistent.

Find the failing stage

WebSocket does not connect
Confirm the hostname, trusted HTTPS certificate, and Asterisk HTTPS port 8089 with its /ws endpoint. Run http show status on Asterisk.
Registration is rejected
Check the extension number and SIP password in FreePBX. Use pjsip show contacts to see whether a WebSocket contact is present after registration.
Reachable, but a call fails with 488 or “Couldn't negotiate stream ... (nothing)”
Registration succeeded, but audio negotiation did not. Compare DTLS media encryption, AVPF, ICE, RTCP mux, certificate paths, and allowed audio codecs for this endpoint.
Microphone permission dismissed
Keep the phone window visible, retry Register or Call, and allow microphone access in Chrome. A reachable SIP contact does not prove that audio can connect.
Caller shows as unknown
Check the incoming SIP INVITE’s From identity. The phone displays the name and number sent by the PBX; KYC name lookup is a separate future feature.

Useful commands on the PBX

sudo asterisk -rx "http show status"
sudo asterisk -rx "pjsip show endpoint 209"
sudo asterisk -rx "pjsip show contacts"

For one failing call, enable SIP logging, reproduce the failure, then disable it:

sudo asterisk -rx "pjsip set logger on"
sudo asterisk -rx "pjsip set logger off"

Closing the phone window leaves the extension registered. Reloading the extension or closing Chrome ends registration and requires the SIP password again.
